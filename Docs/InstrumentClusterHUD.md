# Instrument cluster HUD — first visual version

Implemented in Stagebound-real-scale only. No commit or push. Gameplay, physics, steering, FFB, engine, gearing, scoring, camera, checkpoint logic and audio were not edited for this task. Existing unrelated working-tree changes remain.

1. **Architecture:** RaceHUD retains authoritative data bindings and owns one reusable InstrumentCluster. The cluster owns its procedural skin, with separate tachometer, speedometer, gear, shift lights and vehicle label. ClusterArc generates UI mesh rings/arcs; Images form ticks/needles and TextMeshPro supplies labels. Geometry is generated at initialization or when display parameters change. Configure compares cached values each frame; ordinary updates rotate needles, update text and animate emphasis. VehicleRigLoader is cached when the car binding changes; no per-frame object searches or component lookups were added. Existing vehicle selection changes CurrentDefinition, which updates the display automatically.
2. **Created files:** Assets/Scripts/InstrumentCluster.cs, Assets/Scripts/ClusterArc.cs, Assets/Editor/InstrumentClusterValidation.cs and their Unity .meta files; this document. Generated previews and validation output are under Logs/HUD.
3. **Modified files:** Assets/Scripts/RaceHUD.cs, Assets/Scripts/DriftHUD.cs, Assets/Scripts/VehicleConfig.cs and the AE86, RX7 and SkylineR32 VehicleConfig assets in Assets/Vehicles/Configs. No separate HUD prefab per car is needed.
4. **Display fields:** VehicleConfig.hudDisplay contains HudMaxSpeedKmh, HudMaxRpm and RedlineStartRpm. These fields never set physical limits. Missing or invalid configuration warns once and uses 240 km/h, 9000 RPM and the available engine redline (7500 fallback). Needle values are clamped and non-finite telemetry displays zero.
5. **AE86:** 240 km/h display maximum, 9000 RPM scale, 7500 RPM redline.
6. **Skyline R32:** 300 km/h display maximum, 9000 RPM scale, 7500 RPM redline.
7. **RX-7:** 280 km/h display maximum, 9000 RPM scale, 7500 RPM redline. All three existing engine configurations actually use 7500 RPM; the example R32 8000 redline was therefore not adopted. Speed ranges provide vehicle-appropriate display headroom, not a claim about measured top speed.
8. **Speed scale:** Choose a clean major interval at or above maximum/6 from 1, 2, 2.5, 4, 5 or 10 times a decimal power. AE86 labels every 40; R32 every 50; RX-7 every 50 with a terminal 280 label. Five minor divisions per major interval. Digital speed uses a three-digit format and the existing CarController.SpeedKmh value.
9. **RPM scale:** Labels represent thousands, every 1000 RPM up to a 10000 RPM display range, otherwise every 2000. Five subdivisions per major interval. Digital RPM uses CarController.EngineRPM.
10. **Redline:** The orange-red arc spans RedlineStartRpm to HudMaxRpm. Ticks and labels in that region match the redline color. Each vehicle's config controls its position.
11. **Shift lights:** Seven lights progressively illuminate as actual RPM rises from roughly 80% to 99% of the lower of display redline and engine limiter. First four are mint, last three red. Near 99%, lit lamps pulse subtly between 0.6 and 1 alpha, about 1.9 cycles/second. Speed is not involved.
12. **Needle range:** 225 degrees at zero through a clockwise 270-degree sweep to -45 degrees at the display maximum. Out-of-range telemetry cannot rotate beyond the arc.
13. **Smoothing:** Exponential interpolation, 1-exp(-rate*dt); speed rate 10/s, RPM 18/s (time constants 100 ms and 56 ms). Digital values remain immediate. No artificial bounce.
14. **Gear:** Large central mint text receives CurrentGearText directly, supporting N, R and numbered gears. Changes use a maximum 6% scale emphasis decaying at 7/s.
15. **Timer:** Existing RaceTimer elapsed/best/split/result bindings remain. Timer stays at top center, separate from the gauges. Finish results are preserved. The former vehicle text panel is replaced, so speed/RPM/gear are not duplicated.
16. **Checkpoints:** Existing PassedCheckpoints/TotalCheckpoints appear as secondary mint text in the timer panel. Checkpoint calculations are unchanged.
17. **Drift:** Lower-left panel reads the same DriftScoreSystem/DriftTelemetry. Active score, combo and slip angle become prominent during a running drift; banked score is retained for two seconds; inactive content fades to 12% alpha at 3 alpha units/second. The existing optional debug view remains.
18. **Style Credit:** Persistent mint seconds with three decimals beneath “STYLE CREDIT / TIME REDUCTION.” Uses the existing StyleCredit property without recomputing score-to-time conversion.
19. **Resolution and tests:** Unity rendered all three configurations at 1920x1080 (16:9) and 1920x1200 (16:10). The CanvasScaler uses a 1920x1080 reference and Expand; safe-area anchors keep the cluster lower-right, drift lower-left and timer top-center. Visually inspected previews keep these elements separated and the center clear. Runtime/editor C# compilation passed. Isolated preview validation exercised zero/idle/redline/overrange RPM, overrange speed, angle clamps, N/R/1–6, changing display parameters, unchanged hierarchy during updates, nonempty arc meshes, and actual DriftHUD live/banked/ready presentation branches. These are synthetic UI tests, not a driven vehicle test. Timer preview text is representative; real timer advancement, limiter cycling, transitions while driving and readability against bright/dark tracks still need Play Mode review. No frame-time profiling claim is made.
20. **Placeholder visuals:** Existing TMP font is retained. Dials, needles, hub, lamps and separator are procedural first-version visuals; no external PNG or custom font is required. Preview backgrounds are neutral and do not represent the road scene.
21. **Future artwork:** A tailored automotive font, shaped needle/hub, subtle bezel texture and small icons could refine the skin. These can replace InstrumentCluster/ClusterArc presentation while retaining RaceHUD bindings. No alternate themes were implemented.

## Reviewing in Unity

Enter Play Mode and select AE86, R32 or RX-7 normally. F2 retains panel dragging; Shift+F2 resets positions. The cluster and drift panel use new saved-position keys to avoid inheriting the old panel locations; timer positioning is retained. T retains the existing panel-background control while editing; the circular dial faces remain part of the cluster skin.

For repeatable isolated previews, leave Play Mode and use **Stagebound > Validate and render instrument cluster**. This creates preview scenes only, writes Logs/HUD/validation.txt and six PNGs, and does not alter saved gameplay scenes or HUD position preferences.
